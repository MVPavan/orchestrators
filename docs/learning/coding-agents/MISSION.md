# Mission: Understand coding-agent systems

## Why

Build a systems-engineering understanding of unfamiliar coding agents so their
architecture, operational behavior, and tradeoffs can be evaluated without
depending on prior codebase knowledge or language-level implementation detail.

## Success looks like

- Trace a real Pi or Codex agent turn through control, data, state, trust,
  failure, persistence, and rendering boundaries.
- Explain the system plainly, cite the source of important claims, and name
  what remains uncertain.
- Use CodeGraph, CBM, and Graphify deliberately, knowing what each contributes,
  what it costs, and when source verification is still required.
- Transfer the Pi mental model to Codex without flattening their different
  architectures.

## Constraints

- Learn Pi before Codex; Pydantic AI and Deep Agents remain deferred.
- Focus on systems behavior, not TypeScript/Rust syntax or coding style.
- Prefer source-grounded offline work and avoid unnecessary provider sessions.
- Separate verified fact, inference, and open question.
- Require Feynman teach-back, Socratic repair, and transfer before recording
  mastery.

## Out of scope

- Implementing or modifying the upstream coding agents.
- Exhaustive syntax, API, or package inventories.
- Treating one tracer case study as a statistically generalizable benchmark.
